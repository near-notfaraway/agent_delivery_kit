# 验证、冻结与证据约定

供仓库准备、交付评审、集成验收和协调者共用。按实际改动选择检查，不新增业务验收或降低仓库必需检查。

## 1. 执行前核查

运行命令前先读取相关包初始化、`TestMain`、测试/构建脚本和环境配置，识别外部网络、数据库以及增删改副作用。记录工具链和实际依赖；核对目标地址、资源归属和隔离条件，不把包名、test 字样或默认配置当作安全证据。

涉及真实写入的检查仅在授权且隔离的目标执行。无法证明隔离或缺少运行条件时停止该项执行，保留未执行原因；继续独立安全检查，按第 4 节处理交接条件。

Go 的 `-run '^$'` 只过滤测试函数，仍执行包初始化及 `TestMain`，不能作为安全的只编译命令。需要编译测试代码而不运行测试二进制时，可使用已核实工具链的 `go test -exec true ...`；记录为“只编译，未运行测试”。它仍可能执行构建工具或获取依赖，执行前仍需核查。兼容工具链构建、局部测试、完整测试和真实环境验收分别报告。

固定必要的工具链、模块/lockfile 和获取方式；临时兼容手段保存在隔离位置，明确与目标工具链差异。不能悄悄修改业务依赖来让测试通过。

### 运行能力与替代路径

开始相应阶段前核查实际能力和运行条件，将所用实现、替代路径及证据要求写入既有执行/验证入口。本项目自带 Skills 由 Agent 按阶段直接读取；外部 Skills 按宿主环境的安装方式选用，本项目不自动安装或托管它们。平台文档能力仅在读取相应在线来源时需要，Skill 维护工具不属于普通交付的必装项。

| 场景与必需能力 | 可选实现 | 替代路径及必须保留的结果 |
|---|---|---|
| 读取需求和参考资料 | 本地 Markdown，或在线来源的文档工具 / API | 用户提供完整导出或正文，注明来源、版本和未读取的评论/附件；搜索摘要不能代替正文 |
| 行为变化的 TDD | 编码 Agent 直接执行，或使用辅助测试 Skill | 先添加失败行为测试并确认失败，再做最小实现和验证，保存失败/通过证据 |
| 页面实现 | 按确认方案和仓库既有组件、样式开发，或使用辅助设计 Skill | 使用既有设计系统，仍满足功能、交互和验收要求 |
| 实际代码评审 | 协调者或只读 Reviewer 按 delivery-review 审查 | 人工审阅同一固定差异，记录实际 Reviewer、问题、复核和范围；自检不能称为独立审查 |
| 需求要求的浏览器验收 | 浏览器自动化工具及可选辅助 Skill | 人工在实际浏览器按相同用例执行，记录修订、环境、步骤、实际结果和必要截图/请求响应与数据证据 |
| 数据库、并发或目标环境验收 | 授权的隔离真实资源及客户端/测试工具 | 使用另一种可证明相同语义的隔离真实环境；Mock 不替代真实存储或目标环境验收 |

替换工具且验收范围与证据标准不变时无需重新批准流程。人工路径记录操作者、固定修订、环境、时间、步骤、预期/实际结果和必要证据；退出码不适用时如实说明，不伪造命令日志。能力缺失或证据不完整时保留对应待验/阻塞，继续独立工作；不能因缺少外部 Skill 跳过必需验收，缩减范围仍须真实确认。

## 2. 冻结最小证据

对最终被审阅及验证的内容记录：

| 信息 | 要求 |
|---|---|
| 身份与源码 | 任务/修复 ID、仓库、分支、基线、HEAD；未提交时记录 staged/unstaged diff、相关未跟踪文件及源文件摘要 |
| 相关依赖 | 模块版本、lockfile 或产物摘要，实际获取/解析方式 |
| 运行条件 | 工具链、命令、工作目录、必要框架/架构/时区、隔离目标和配置摘要；不保存凭证 |
| 结果 | 执行时间、退出码、通过/失败/未运行/只编译及关键输出、用例覆盖和真实/Mock 边界 |
| 审阅关联 | Reviewer、最终结论、问题复核、实际批准范围及证据 |

摘要使用内容哈希或其他可复核的固定标识。只冻结相关内容；不复制整个私人工作区、不将环境变量中的凭证写入日志。不能用旧 HEAD 代替未提交实现。

冻结和运行副本的保留范围、尝试与当前入口关联按 [产物管理](artifact-management.md)，不将局部复验写成全套重跑。

提交后核验完整 commit、父提交和源 blob 是否对应被冻结差异。代码、相关依赖或验证配置变化时，更新审阅范围并重验受影响部分。仅提交元信息或路径发生变化，且源码、依赖、工具链和相关运行条件等价时，可记录等价核验并复用已有测试；不能因成功提交就宣称测试重新运行。

## 3. 可消费交接

Git commit 证明源码身份，不证明下游能获取。交接需同时记录固定修订、接口/数据合同、可解析的确切模块版本或产物、获取方法、实际解析/构建证据和兼容说明。

没有远端发布授权时，可从确切提交生成固定本地产物并记录摘要与获取限制。下游在隔离环境实际解析验证。浮动分支、活跃源码目录或浮动 `replace` 不能作为最终交付版本；临时路径替换须明确用于何种验证，最终仍须提供固定输入。push/发布不能从依赖需要推导授权。

真实集成经过实际 handler、默认中间件/编码器和消费者，覆盖相关正常、无结果/空值和错误信封。关键 helper 复用前核查正常与默认/降级路径；必要数据库/并发/浏览器证据不能由 Mock 或工具成功返回替代。

## 4. 检查失败和例外

必需检查失败或未运行时保留原结果，默认阻塞相应验收。证明“既有失败”必须提供选定基线修订上的同条件对照；没有对照只能记录未证实，不能仅凭报错位置归因基线。

统一记录：

- 失败/未运行的命令、工作目录、工具链、退出码、关键输出及源摘要。
- 基线完整 commit、同条件对照命令与证据，或无法对照的原因。
- 对本次改动和验收的影响，以及实际已通过的局部/替代检查。
- 例外批准 ID、批准人、时间、依据、任务和阶段范围；未批准时写明待批准。
- 尚待补验的事项、目标条件与责任；真实环境限制单独保留。

例外批准只改变指定阶段的交接条件，不将失败改为通过、不批准未审阅的新改动、不扩大整体验收或部署结论。已有充分且范围相符的批准直接沿用。无有效批准时继续可进行的独立工作，不能伪造完成。

## 5. 证据入口与保留

证据位置、尝试编号、固定产物、脚本复用、临时资源生命周期和交接材料检查统一遵循 [产物管理](artifact-management.md)。恢复旧需求沿用已有入口和证据，不自动迁移、清理或生成竞争报告。日志写入失败与被验证动作失败分别判断，补齐缺失关联不能冒充重新执行。
